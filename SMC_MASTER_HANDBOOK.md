## 1. System Overview & Architecture

SMC is a dynamically typed, interpreted programming language and virtual machine runtime (`DexterVM`). The runtime executes an Abstract Syntax Tree (AST) generated by a fault-tolerant, typo-tolerant lexer and recursive-descent Pratt parser.

```
+-------------------------------------------------------------------------+
|                              Source Code                                |
+-------------------------------------------------------------------------+
                                     |
                                     v
+-------------------------------------------------------------------------+
|                  SmcLexer (Wobble Opcode Resolution)                    |
|  - Exact Synonym Mapping                                                |
|  - Levenshtein Edit Distance Matching (len <= 4: d=1; len >= 5: d=2)    |
+-------------------------------------------------------------------------+
                                     |
                                     v
+-------------------------------------------------------------------------+
|                    SmcParser (Pratt Parsing Engine)                     |
|  - Precedence Binding                                                   |
|  - Multi-Frame Slicing (HexaPhaseSlicer: +0, +1, +2, -0, -1, -2)         |
+-------------------------------------------------------------------------+
                                     |
                                     v
+-------------------------------------------------------------------------+
|                         DexterVM Runtime Engine                         |
|  - Call Stack Frames (Local Scope)                                      |
|  - Ephemeral Memory Table (TTL Auto-Decay)                              |
|  - Content-Addressable Ring Registry (Shape Binding)                    |
|  - Python CPython FFI Bridge (Module Marshalling)                       |
|  - Embedded HTTP Server (Multi-threaded Request Pipeline)               |
+-------------------------------------------------------------------------+
```

### 2.2 Wobble Typo-Tolerance Algorithm
When an identifier does not match any known keyword or built-in function name:
1. Built-in function identifiers (`len`, `push`, `pop`, `str`, `int`, etc.) and single-character tokens are exempt from mutation matching.
2. The Levenshtein distance $D(s, k)$ between raw token $s$ and canonical synonym $k$ is computed.
3. Matching threshold:
   $$\text{Max Allowed Distance } D_{max} = \begin{cases} 1 & \text{if } |s| \le 4 \\ 1 & \text{if } 5 \le |s| \le 6 \\ 2 & \text{if } |s| \ge 7 \end{cases}$$
4. If $D(s, k) \le D_{max}$, $s$ is rewritten to $k$ and tokenized with a mutation repair log.

## 3. Type System & Value Semantics

### 3.1 Data Types
* **Number (`int`, `float`):** 64-bit IEEE-754 floating-point or signed integer.
* **String (`str`):** UTF-8 character sequences. Supports escape codes (`\n`, `\t`, `\"`, `\'`, `\\`) and template interpolation (`` `Value: ${expr}` ``).
* **Boolean (`bool`):** `true` and `false`.
* **Null (`null`):** Represents empty/uninitialized value.
* **List (`list`):** Dynamic ordered array (`[1, 2, "three"]`). Supports safe negative indexing (`arr[-1]`).
* **Dictionary (`dict`):** Hash map (`{"key": "value"}`).

### 3.2 Ephemeral TTL Memory (Acme Items)
Variables declared via `acme(ttl=N) var = expr` are stored in an active TTL table:
* Structure: `TtlItem(value: Any, ttl: int)`.
* **Decay Trigger:** Each statement execution or incoming HTTP request increments `execution_steps` by $1$ and decrements all active TTL values by $1$.
* **Expiration:** When $\text{TTL} \le 0$, the entry is deleted from memory.

## 4. Operator Precedence & Evaluation Rules

Expressions are evaluated according to the following precedence hierarchy (highest to lowest):

| Precedence Level | Operators | Description | Associativity |
| :---: | :--- | :--- | :---: |
| **7** | `()`, `[]`, `.` | Grouping, Indexing, Member Access | Left-to-right |
| **6** | `!`, `not`, `-` (unary) | Logical Negation, Arithmetic Negation | Right-to-left |
| **5** | `*`, `/`, `%` | Multiplicative Operations | Left-to-right |
| **4** | `+`, `-` | Additive Operations, String Concatenation | Left-to-right |
| **3** | `<`, `<=`, `>`, `>=` | Relational Comparisons | Left-to-right |
| **2** | `==`, `!=` | Equality / Inequality | Left-to-right |
| **1** | `&&`, `and` | Logical Conjunction (Short-circuiting) | Left-to-right |
| **0** | `\|\|`, `or` | Logical Disjunction (Short-circuiting) | Left-to-right |

## 5. Scope & Variable Resolution

Variables are resolved in the following strict order:
1. **Local Call Stack:** Current activation record frame `call_stack[-1][name]`.
2. **Ephemeral Memory:** `ttl_memory[name].value` (if unexpired).
3. **Global Scope:** `variables[name]`.
4. **Undefined Reference Default:** Unset variables evaluate to `0` (or `null` in boolean context) without throwing fatal runtime exceptions.

```
Variable Lookup: get_var(name)
       |
       +---> In Local Stack Frame? ------> YES: Return local value
       |              | (NO)
       +---> In TTL Memory (Unexpired)? -> YES: Return TTL value
       |              | (NO)
       +---> In Global Variables? -------> YES: Return global value
       |              | (NO)
       +---------------------------------> Default: Return 0
```

## 6. Execution Semantics & Subsystems

### 6.1 Function Definition & Calls
* **Syntax:** `fn name(param1, param2) { ... return expr }`
* **Local Scope Isolation:** Each function call pushes a new frame `{}` onto `call_stack` and pops it upon return.
* **Recursion Guard:** Execution is hard-limited to 100 nested stack frames to prevent stack overflow crashes.

### 6.2 Content-Addressable Ring Dispatch
* **Registration:** `bind(ring="KEY") { ... }` registers an AST statement block under `"KEY"` in `planeteer_rings`. Multiple blocks can be bound to the same key.
* **Dispatch:** `dispatch "KEY"` evaluates all blocks registered under `"KEY"`.
* **Watchdog Fallback:** If `dispatch` targets an unbound key, the runtime executes the AST block registered via `fallback { ... }`.

### 6.3 HexaPhase 6-Track Multiplexing
* **Syntax:** `hexaphase <expr> { ... }`
* **Semantics:** Evaluates `<expr>` as string $S$ of length $N$ and decomposes it into 6 channels stored in variable `hexaphase_channels`:
  $$\text{Phase }+0 = \{ S_i \mid i \equiv 0 \pmod 3 \}$$
  $$\text{Phase }+1 = \{ S_i \mid i \equiv 1 \pmod 3 \}$$
  $$\text{Phase }+2 = \{ S_i \mid i \equiv 2 \pmod 3 \}$$
  $$\text{Phase }-0 = \{ \text{rev}(S)_i \mid i \equiv 0 \pmod 3 \}$$
  $$\text{Phase }-1 = \{ \text{rev}(S)_i \mid i \equiv 1 \pmod 3 \}$$
  $$\text{Phase }-2 = \{ \text{rev}(S)_i \mid i \equiv 2 \pmod 3 \}$$

### 6.4 Programmed Ribosomal Frameshifting (`slip`)
* **Syntax:** `slip(offset)`
* **Semantics:** Modifies the VM execution track offset:
  $$\text{current\_phase\_offset} \leftarrow (\text{current\_phase\_offset} + \text{offset}) \pmod 3$$
  Sets variable `current_phase = current_phase_offset`.

### 6.5 Attenuator Pause Gates
* **Syntax:** `attenuator(threshold = <expr>) { ... }`
* **Semantics:** Evaluates numeric threshold and arms a rate-limiting execution boundary for nested statements.

### 6.6 Python Ecosystem FFI Bridge
* `py_import "module_name" as alias`: Imports a Python module into `py_modules`.
* `py_call("module.function", *args)`: Dynamically resolves and invokes Python callables, automatically marshalling arguments and return types between Python and SMC representations.
* `py_eval("expr_str")`: Evaluates arbitrary Python expressions with access to `math`, `random`, `datetime`, `json`, `time`, `os`, `sys`, and all imported modules.

### 6.7 Embedded HTTP Server
* **Syntax:** `serve_http(port: int, handler_fn: str)`
* **Semantics:** Spawns a multi-threaded `HTTPServer` on `0.0.0.0:port`. For each incoming request (`GET`, `POST`, `PUT`, `DELETE`), constructs a request dictionary `{"path": str, "method": str, "headers": dict, "body": str}` and invokes `handler_fn(req)`. Handler must return a response dictionary `{"status": int, "content_type": str, "body": str}` or string payload.

## 8. Runtime Error Handling & Safety Guarantees

| Fault Condition | DexterVM Handling Policy |
| :--- | :--- |
| **Division by Zero (`x / 0`)** | Intercepted by `_div_guard`; emits log and returns `0`. Never terminates process. |
| **Out-of-Bounds List Index** | Safe indexing returns `0` (or `null`); negative indices wrap (`arr[-1]` $\rightarrow$ `arr[len-1]`). |
| **Missing Dictionary Key** | Hash lookup returns `0`; never raises `KeyError`. |
| **Stack Overflow / Recursion** | Hard limit of 100 frames; emits `[RECURSION_GUARD]` and unwinds cleanly. |
| **Module Import Cycles** | Tracks imported file paths in `imported_modules`; duplicate imports are ignored. |
| **Type Coercion Failures** | Non-string additions with strings safely coerce values via `str(val)`. |
| **Uncaught Dispatch Targets** | Dispatches to unbound keys execute `fallback` block if defined, or silently pass. |
